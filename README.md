# Space Fractions Code Agent

A lightweight **code-generation agent** inspired by the mechanisms behind
[Claude Code](https://github.com/anthropics/claude-code). It reads a software
architecture specification and autonomously generates a complete, runnable
project from it — a native **local desktop game** called Space Fractions.

Built as Task 1 of the CSC scholarship evaluation.

---

## ✨ Features
- Reads two architecture documents and converts them into a structured spec
- Plans its own file manifest, then generates each file with full context of
  what it has already written (the same read → plan → act loop Claude Code uses)
- Produces a complete **local, offline desktop application** — no web server,
  no browser required
- Ships with a dependency file, a README, and a passing automated test suite

---

## 🚀 Quick Start

### Environment Setup
```bash
git clone <your-repo-url>
cd space-fractions-agent
pip install -r requirements.txt
```

Set an API key for whichever LLM provider you have (the agent auto-detects it):
```bash
export GEMINI_API_KEY=your_key_here        # https://aistudio.google.com/apikey
# or
export ANTHROPIC_API_KEY=your_key_here     # https://console.anthropic.com
```
(On Windows, use `set` instead of `export`.)

### Run the agent
```bash
python main.py
```
This reads `Architecture_Documentation.md` and `Architecture_View.md`, plans
the file list, and generates the full project into `game_output_local/`.

To force a specific provider:
```bash
python main.py --provider gemini
python main.py --provider anthropic
```

To regenerate everything from scratch instead of reusing files from a
previous run:
```bash
python main.py --fresh
```

### Run the generated game
```bash
cd game_output_local
python space_fractions_app.py
```
A native desktop window opens directly on your machine — no server, no
browser tab. Click **Start Mission** to play.

### Run the tests
```bash
cd game_output_local
pip install -r requirements.txt
pytest
```

## What it does

Given two architecture documents as input:

| Input file | Contents |
|---|---|
| `Architecture_Documentation.md` | Requirements, components, API contracts, data schemas, deployment spec |
| `Architecture_View.md` | 11 PlantUML architectural diagrams across 5 views (Scenario, Logic, Process, Development, Physical) |

...the agent produces a full project:

- Project directory structure
- A native desktop game (intro screen, main menu, fraction questions, ending scene) built with Python's built-in Tkinter toolkit
- `requirements.txt`
- `README.md`
- Test cases

The generated target is **Space Fractions** — an offline, local desktop
learning tool that helps sixth-grade students practise fractions.

## How the agent works

The agent follows the same core loop that powers real AI coding agents:
**read context → plan → act → repeat**.

```
┌──────────────────────────┐
│ 1. READ                  │   parser.py
│   .md files → JSON       │   Markdown sections & fenced code blocks are
│                          │   parsed into a structured, machine-readable spec
└───────────┬──────────────┘
            ▼
┌──────────────────────────┐
│ 2. PLAN                  │   code_agent.plan_file_list()
│   spec → file manifest   │   The LLM decides WHICH files the project needs
│                          │   and what each one is responsible for
└───────────┬──────────────┘
            ▼
┌──────────────────────────┐
│ 3. ACT (loop)            │   code_agent.generate_file()
│   for each file:         │   Each file is generated with the spec AND the
│     generate → write     │   list of already-written files as context, so
│                          │   imports and filenames stay consistent
└───────────┬──────────────┘
            ▼
   game_output_local/  ← complete, runnable local desktop app
```

The key property that makes this **agentic** rather than a single prompt: the
agent is not told what files to create. It determines the file manifest itself
from the architecture spec, then executes against its own plan, carrying
accumulated state (previously written files) forward into each step.

## Design notes

**Why a provider adapter?** `llm_provider.py` hides Gemini and Anthropic behind
a single `complete(prompt, max_tokens)` interface. The agent core has no
knowledge of which model is behind it, so swapping providers requires no
changes to the agent logic.

**Why convert the docs to JSON first?** The task instructions recommend it, and
it pays off in practice: raw markdown wastes context on formatting, while the
structured form lets the agent address specific parts of the spec (component
list, OpenAPI contract, SQL schema) directly and keeps prompts within budget.

**Why a local desktop app instead of a web app?** The game runs as a plain
Tkinter window using only Python's standard library — no Flask server, no
browser, no network port. Anyone can run it with a single command and no
setup beyond having Python installed.

**Error handling.** LLM calls retry with exponential backoff. Responses are
stripped of markdown fences, and plan output is validated as JSON with a
fallback extractor, since models occasionally wrap JSON in prose.

## Generated output

`game_output_local/` contains a complete, tested implementation of the Space
Fractions game: a space-themed 10-question fraction quiz, randomly generated
on every playthrough, running as a native Tkinter desktop application, with a
README and a passing pytest suite (question-bank integrity, scoring logic,
and rank thresholds). See `game_output_local/README.md` for details.

> **Note:** an earlier, web-based version of the generated game (Flask +
> HTML/CSS/JS) is kept in `game_output/` for reference. The local desktop
> version in `game_output_local/` is the current, intended output.
